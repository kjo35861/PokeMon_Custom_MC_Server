# 관리자 페이지 · 메뉴0.21.0 / 모드0.13.0

구현·코드·모의 화면 검사 완료, 실제 게임의 OP/거래 편집은 사용자 확인 대기입니다. 사용자 월드·계정·OP 목록을 도구로 조작하지 않았습니다.

## 접근 권한

메인 메뉴 상단의 관리자 버튼은 서버가 인증한 플레이어에 대해 `hasPermissionLevel(2)`가 참일 때만 표시합니다. 즉 OP 레벨2·3·4 또는 동등한 싱글플레이 치트 권한이 필요합니다. OP 레벨1은 관리자 변경 권한에 포함하지 않습니다.

버튼 숨김은 표시 처리이고, 실제 보안은 `pocketmate:admin`의 모든 조회/검색/변경 요청에서 서버 권한을 다시 검사하는 방식입니다. 클라이언트의 권한 플래그는 받지 않습니다. 권한 회수 후 다음 요청은 즉시 거절하며, 클라이언트가 거절/권한 확인 실패를 받으면 버튼을 숨기고 관리자 페이지를 닫습니다. 권한 표시는 주기적으로 갱신되므로 OP 승격/회수 직후 화면 반영에 수초가 걸릴 수 있습니다.

## 제공 기능

- **상점 목록:** 분류·구매/판매/미사용 필터, 이름/ID 검색, 페이지24종. 등록된 게임 아이템을 검색하여 추가하거나 기존 품목의 분류·구매/판매 활성 여부·개별 기준가를 수정합니다. 목록 제외는 구매만/판매만/둘 다 선택합니다. 유저가 보유한 아이템을 삭제하는 기능이 아닙니다. 미사용 필터에서 다시 수정해 복구할 수 있습니다.
- **가격·점검:** 기본 구매/판매가, 랜덤 판매가 사용, 주기60~604800초, 편차0~40%. 개별 품목 설정이 기본가보다 우선합니다. 판매가가 구매가보다 낮아야 합니다.
- **점검 스위치:** 상점 구매·상점 판매·영지 생성/영토 구매·임무 보상 수령을 독립적으로 정지/재개합니다. 공통 점검 안내를 넣을 수 있습니다. 기존 재화·인벤토리·영지 소유권·임무 진행도는 유지하고 임무 행동 집계도 계속합니다. 모든 스위치의 기본값은 꺼짐입니다.
- **운영 현황:** 영지 저장소 연결·영지/청크 수·최대 레벨/면적/인원, 일일 임무 초기화 시각과 Pixelmon 연결 여부를 조회합니다. 기존 인원5명 등 게임 규칙은 바꾸지 않습니다.
- **변경 기록:** 누가/언제/어떤 항목을 바꿨는지 기록합니다. 표시30건, 서버 저장100건. 닉네임과 UUID를 함께 남깁니다.

## 유지하는 품목 규칙

판매는 기존 바닐라 광물·농작물 허용 품목으로 제한합니다. 일반 장비나 주괴·조각 등을 임의로 판매 등록할 수 없습니다. 광물 구매 분류에는 기존 미제련 광물만 넣을 수 있으며, 운영용/광물 압축/직접 분해 차익 제외 블록은 구매에 재등록하지 못합니다. 농작물로 판매하는 꽃은 구매 분류가 장식이어도 판매 시 농작물로 분류됩니다. 모드 아이템은 해당 서버 레지스트리에 실제 존재해야 추가할 수 있습니다. 기본 포켓몬 분류는 계속 비어 있으며 Pixelmon/NeoForge 연동을 구현한 것은 아닙니다.

## 저장·동시 편집

서버의 config/pocketmate-shop.json에 저장합니다. 기존 평면 가격 설정은 자동으로 읽습니다. 첫 관리자 저장 시 schema1 구조로 바꾸고 이전 파일을 pocketmate-shop.json.bak에 보존합니다. 이후에도 매 저장 직전의 한 버전을 .bak에 보존합니다. JSON이 손상되면 초기화하지 않고 상점 변경을 중단합니다. 수동 복구는 게임/서버가 종료된 상태에서 백업을 확인해 수행해야 합니다.

모든 수정은 클라이언트가 본 revision을 함께 전달합니다. 다른 관리자가 먼저 저장했다면 덮어쓰지 않고 새로고침을 요청합니다. 임시 파일 작성→기존 파일 백업→원자적 교체 후 메모리 설정을 바꾸며, 저장 실패 시 기존 활성 설정을 유지합니다. 지원하지 않는 파일시스템에서는 일반 교체로 대체합니다.

새 목록·가격·점검 저장은 기존 견적 버전을 무효화합니다. 이용자가 예전 가격/목록으로 확정하면 거래 전에 거절하며 재화·인벤토리를 변경하지 않습니다.

## 적용·검증 범위

이번 기능은 서버 모드가 변경되므로 최초0.13.0 적용에는 게임/서버 재시작이 필요합니다. 이후 페이지에서 저장한 설정은 즉시 반영합니다. /webgui reload는 웹 파일을 바꿨을 때만 사용합니다.

Java105개 검사(기존97+관리자8), 비OP 조회/변경 거부·기존 설정 마이그레이션/백업·항목 변경/제외·안전 품목 제한·동시 편집·점검/랜덤 설정 영속화·저장 실패·손상 파일 보존·기록100건 상한을 검사했습니다. 모의 브라우저에서 OP 버튼 숨김/표시, 직접 경로 거부, 추가/검색/가격 수정/제외, 점검 설정, 권한 회수,2테마/4화면 크기와160% 글자를 검사했습니다. 실제 플레이어 권한과 게임 거래/아이콘은 직접 테스트하지 않았습니다.
