# 메가진화 모델 크기 보정 0.1.3

사용자 제공 게임 화면의 루카리오 Z 거대화에 따라 추가·보완45폼을 검사했다. 이 문서의 수치는 BMD 기준 자세를 정적으로 측정한 값이며, 게임에서 최종 렌더링한 실측치는 아니다.

## 원인과 보정 방식

이전 생성기가 외부 모델43개에 모두 scale=5.0을 적용했다. 모델 원본의 높이 단위가 서로 다른데 이 값을 공통으로 사용하여 기본 높이가 약6–31블록까지 커졌다. 루카리오Z는 원본 높이100단위에 배율5가 적용된 사례다.

설치된 Pixelmon9.4.3의 AbstractPokemonRenderer.scale에서 모델단위 변환1/16을 확인하고, 각 BMD의 전체기하 기준자세 Z높이를 읽어 `새 배율 = 카탈로그 신장(m) × 16 / 모델 원본 높이`로 계산했다. 일반색/이로치와 싸리용3원형·지가르데2원형의 파생메가폼 모두 같은 기준으로 보정했다. 이미지나 모델 파일을 임의로 축소한 것이 아니라 해당폼의 모델배율을 수정했다.

Pixelmon의 별도 graphics scale-models-up(1.3배), 개체성장도, 보스등급배율, 다이맥스 등 기존배율은 유지한다. 예를 들어 루카리오Z의 기준높이1.3블록은 그래픽1.3배가 켜져 있으면 성장도/보스 등 다른배율 적용전1.69블록이다.

기존 Pixelmon모델을 사용하는 망나뇽·아쿠스타2개도 원본기하와배율을확인했다. 이들은 이전 생성기의 공통5.0을 쓰지 않았고 정상범위에 있어 기존모델설정을유지했다. 원래 메가루카리오/리자몽 등 보완카탈로그대상이 아닌 기본모드는크기를바꾸지않았다.

## 데이터와 검증 범위

- 직접 작성한 BMD1/2 경계상자 reader가 모델43개를 읽었다. 일부 원본Pixelmon XZ푸터 생략은 Java로더처럼 모델레코드소비기준으로 처리하며, 실제기하가잘리거나 남은payload가있으면거부한다. 입력모드클래스는실행하지않았다.
- 계약검사8개: 기존스톤/폼/스탯/능력치/복귀/네이티브연결/리소스참조검사에 더해 모든외부모델·일반/이로치·원형별height 정규화, BMD버전/정상레코드/잘린데이터검사 포함.
- 기존 네이티브 메가폼2개, 모든 일반폼/기술/능력치/스폰조건 및 모델·텍스처바이트는 보존한다. 충돌상자의 height/dimensions와 growth_data도 이번배율보정에서변경하지않는다. Pokemon.setForm의 기존 remapSizeForGrowthChange가 원형/메가 사이 성장도를 처리함을 정적으로 확인했다.
- 이 작업에서는 실제 게임/Prism/서버 실행·종료·화면조작을 하지 않았다. 기본자세 경계상자 기준으로맞춘것이며 idle/전투애니메이션의 매프레임 높이, 날개/꼬리 움직임, 보스/성장도에따른 실제크기는사용자확인이필요하다.

[Pixelmon GrowthData API](https://reforged.gg/docs/1211/com/pixelmonmod/pixelmon/api/pokemon/growth/GrowthData.html), [공식 개발진의 크기/충돌상자 설명](https://pixelmonmod.com/tracker.php?p=2&t=22680)을 참고했다. 9.4.3의 실제 배율은 설치JAR 코드로확인했다.

## 적용

클라이언트 보완JAR/런처배포본은0.1.3으로 갱신했고 이미설치된 자체월드데이터팩1개도 교체했다. 높은우선순위의 이전데이터팩이 남으면 배율5.0이다시적용될수있다. 외형리소스팩의BMD/PNG는변경하지않았다.

실행중 서버의0.1.2 JAR는 Windows파일잠금으로 교체할수없어 `pocketmate-multiplayer-prep/pending-mega-size-013`에 새JAR/고정해시/적용스크립트를준비했다. 다음 run.bat는Java시작전에업데이트를검사·교체하고이전JAR를mods밖으로백업한다. 잠금이나해시문제가있으면새서버시작을중단한다. 실제서버교체완료로기록하지않는다. 가짜JAR fixture에서변조해시거부·검사전용·정상교체·재실행안전성을확인했고실제서버큐는검사전용으로통과했다.

사용자가 서버콘솔에서stop으로완전종료후run.bat를실행하고게임도재시작해야한다. 서버를재시작하지않으면접속시이전종족크기데이터를받을수있다. 에이전트는프로세스를종료하거나시작하지않았다.

## 후속 파일 배치 상태

같은 날 관리자 상점 수정 작업 중 대상 게임/서버 프로세스가 없는 것을 확인하고 대기 큐를 실제 적용했다. 서버 mods도0.1.3으로 교체됐으며 ready 표시를 제거했다. 이전 대기 기록/증거는 당시 상태로 보존한다. 실제 서버 실행이나 모델 렌더링을 에이전트가 확인한 것은 아니다.
