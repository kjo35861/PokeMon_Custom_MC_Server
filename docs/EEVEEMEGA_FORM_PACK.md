# 포켓메이트 메가진화 0.1.3

> 0.1.6부터 중복 나이트 9종은 Pixelmon 원본 폼에 연결된다. 호환 모드 카탈로그는 36종이며 포켓메이트 전용 나이트 34종을 포함한다. 별도 Eevee 복구 리소스팩 ZIP은 최신 [클라이언트 배포 목록](client-pack/README.md)에서 제외했다. 아래 숫자와 검증은 초기 구현 기록이다.

2026-11-25 작성. **생성·빌드·정적 검사 완료, 실제 게임 확인 대기.** 게임·서버·Prism은 에이전트가 실행하거나 종료하지 않았다.

현재 보완 모듈은 **포켓메이트 메가진화 0.1.3**, 배포 파일은 `pocketmate-mega-evolution-0.1.3.jar`다. 0.1.2에서 추가한 상세 툴팁 표시 보완을 유지하고, 0.1.3에서 외부 모델43개에 잘못 공통 적용했던 배율5.0을 모델별 신장 기준으로 보정했다. 실제 아이템 ID·저장 데이터·능력치·진화 연결은 유지했다. 함께 필요한 EeveeMega 기반 파일은 파일명/모드 표시명만 바꾼 `PocketMate_Mega.jar`다. 모델 크기 문제는 수정·확인 중이며 실제 게임 화면은 사용자 확인 대기다.

## 구성과 현재 배치

대상은 Minecraft **1.21.1**, NeoForge **21.1.248**, Pixelmon **9.4.3**, EeveeMega **1.1.0**이다. 다른 버전을 지원한다고 주장하지 않는다. 생성기는 분석한 입력 JAR·복구팩의 SHA-256도 검사한다.

- `pocketmate-mega-evolution-0.1.3.jar`: 종족 데이터·필요한 외형·전용 크리에이티브 탭·현재 폼 검사·캐시 갱신·지가르데 HP 처리·툴팁 표시·모델별 크기 보정을 묶었다. EeveeMega 기반 `PocketMate_Mega.jar`와 **함께** 설치한다.
- `pocketmate-eeveemega-data.zip`: 같은 종족 데이터를 담은 독립 데이터팩. 테스트 월드에 명시적으로 배치하여 모드 기본 데이터보다 높은 우선순위를 확보했다.
- `pocketmate-eeveemega-resources.zip`: 보완 JAR에도 들어 있는 외형만 별도로 묶은 리소스팩. 보완 JAR을 쓰는 구성에서 별도로 켤 필요는 없다. 원래 서버의 HUD·칭호·장식·폰트는 가져오지 않았다.
- 빌드 결과와 검증·배치 manifest는 사용자 Downloads의 `pocketmate-eeveemega-compat-2026-11-25/`에 저장했다. 실제 월드 본문·플레이어 데이터·계정·기존 설정은 수정하지 않았다.

최초 작업에서 테스트 인스턴스의 보완 JAR 및 단일 로컬 월드 데이터팩을 배치했다。 이후 전용 PIXELMON 서버에도 설치했다. 현재 클라이언트와 로컬 런처 배포본/승인 목록은0.1.3이며, 기존 로컬 월드에 설치했던 자체 데이터팩1개도 높은 우선순위의 잘못된 배율이 남지 않도록 갱신했다. 월드 저장 본문과 개체 NBT/옵션은 수정하지 않았다. 서버는 처음0.1.2 실행 중 JAR 잠금으로 교체 대기 큐를 준비했다. 후속 관리자 상점 수정 작업에서 대상 서버 프로세스가 없는 것을 확인하고 그 큐를 실제 적용해 서버 파일도0.1.3으로 교체했다. 실제 서버 시작과 모델 크기 렌더링을 검증한 것은 아니다.

## 메가진화 범위와 조건

- 메가 **45폼**, 종족 JSON **44개**. 싸리용 3폼·지가르데 10%/50%의 원래 모습 복귀를 위해 내부 소스→대상 연결은 **48개**다.
- EeveeMega 스톤 **43개**를 연결했다. 38개는 기존 이름/번호를 보존했고 이름이 없던 예약 번호 54~58은 호환팩에서 새로 정의했다. 망나뇽·아쿠스타는 Pixelmon 본래 스톤을 사용한다.
- 54 히드런, 55 다크라이, 56 마기아나, 57 제라오라, 58 싸리용. 이 다섯 번호는 원래 서버의 비공개 설정을 복구한 것이 아니다. 확인되지 않은 그림을 다른 스톤의 공식 아이콘이라고 붙이지 않고 자수정 조각 공용 아이콘을 사용한다.
- HP/공격/방어/특공/특방/스피드, 타입, 특성을 메가 폼별로 지정했다. 상세 값과 개별 스톤 ID는 [연결표](EEVEEMEGA_FORM_CATALOG.md)에 있다.
- 기본 폼의 기술·일반 진화·성별·기본 능력치는 보존한다. 기존 네이티브 메가스톤 연결과 메가 폼의 기존 아이템 메타데이터도 보존한다. 앱솔·루카리오·한카리아스는 기존 메가와 새 메가 Z를 다른 스톤으로 구분한다.
- 일반 플라엣테와 알로라 라이츄에는 새 메가스톤을 연결하지 않는다. 플라엣테는 `az`(영원의 꽃)만 허용한다. 싸리용과 지가르데의 원래 폼은 임시 폼의 `defaultBaseForm`으로 분리한다.
- Pixelmon의 기존 메가진화 절차를 사용한다. **트레이너가 키스톤/메가링을 착용하고 포켓몬이 맞는 메가스톤을 지녀야 한다.** 전투에서는 메가 버튼을 사용하고, 필드에서는 원래 모드의 스톤 상호작용을 따른다. 소유권·쿨다운·소비·취소 이벤트·기존 배틀 제한을 우회하지 않는다.

## 보완 코드

`MegaStoneGuardMixin`은 필드 사용 시 **현재 종족 폼**의 매핑을 검사한다. 원래 EeveeMega의 종족 단위 컴포넌트만으로 일반 플라엣테나 지역 폼이 잘못 진화하는 것을 막고, 공유 스톤으로 진화하는 싸리용·지가르데에는 해당 원래 폼에 맞는 대상 컴포넌트를 만든다. 이미 메가인 폼에서 재진화도 거부한다.

서버 시작/데이터팩 동기화 시 범용 스톤 캐시와 `/megastone`의 정적 캐시를 함께 비운다. `ZygardeHealthMixin`은 메가 진입/해제에서 최대 HP를 재계산하고 남은 HP 비율을 보존한다. 배틀 AI 시뮬레이션과 끝난 배틀에는 적용하지 않는다. 배틀 중 수치와 패킷의 실제 표시 결과는 사용자 검증이 필요하다.

원본 EeveeMega는 9.3의 `BattleController` 클래스 API로 컴파일되어 있다. 9.4.3에서는 이것이 인터페이스이고 기존 `globalStatusController`, `participants`, `battleTurn` 필드는 접근자 메서드로 바뀌었다. `EeveeApiPlugin`과 7개 선택 Mixin으로 원본의 해당 필드 접근/가상 호출 12곳을 9.4 인터페이스 호출로 변환한다. 특성 5종과 진단 명령어 2개가 대상이다. 원본 JAR을 고치거나 원본 클래스를 재배포하지 않으며, 제공된 대상 파일에 대한 바이트코드 변환·호출 대상 존재·스택 분석을 별도 JUnit으로 검사했다.

크리에이티브에 **포켓메이트 메가진화** 탭을 추가해 사용되는 스톤 45개만 보여 준다. 사용하지 않는 128개 예약 아이템 전체를 공개하지 않는다. OP용 `/function pocketmate_mega:stones`도 같은 목록을 지급한다. 원래 `/megastone all`은 EeveeMega 네임스페이스 43개를 지급 대상으로 삼으며, 네이티브 망나뇽·아쿠스타 스톤은 별도다.

0.1.2의 `MegaTooltipClient`는 클라이언트에서만 ItemTooltipEvent를 구독한다. 상세 툴팁의 현재 아이템 등록ID와 정확히 일치하는 줄만 바꾸고 스타일을 보존한다. 다른 모드·아이템 이름·설명에 포함된 명령문은 바꾸지 않는다. `/give`와 저장 데이터의 실제 ID는 계속 `eeveemega:...`다. 리소스팩만으로 내부ID 표시 줄을 바꾼 것으로 설명하지 않는다.

스폰 경로는 [현재 서버의 전체 메가보스 조건표](MEGA_BOSS_SPAWNS.md)에 정리했다. 전용 메가보스 58세트/59조건과 보완45폼의 경로를 구분하며, 자연 스폰 세트를 새로 추가한 것은 아니다.

0.1.3 크기 보정은 [45폼 모델 크기 점검표](EEVEEMEGA_MODEL_SIZES.md)에 정리했다. BMD기준자세 Z높이와 Pixelmon의1/16단위변환으로 외부43모델의 개별배율을 계산했다. 네이티브2모델, 개체성장도와 보스배율 및 그래픽1.3배 옵션은 유지했다. 포켓몬마다 같은 배율을 다시 넣거나 모델/텍스처파일을 변형하지 않았다.

## 실제 검사와 한계

- Python 계약 검사 **6개 통과**: 소스 해시, 전체 스톤↔폼/능력치, 다른 스톤 거부, 지역·영원의 꽃·복귀 조건, 기존 데이터/네이티브 아이템 메타데이터 보존, 첫 폼 상속 차단, 모든 모델/텍스처 참조 해석을 검사한다. 검사항목은 여섯 테스트 메서드에 묶여 있다.
- Java ABI 검사 **2개 통과**: 실제 원본 7클래스의 12개 레거시 명령 변환, 현재 Pixelmon 인터페이스의 대상 메서드 존재, ASM 스택/재직렬화 검사, 중복 변환 방지를 확인했다. 대상 모드 클래스를 실행한 테스트가 아니다.
- 생성된 독립 ZIP 2개와 초기 최종 JAR 전체 CRC 통과. 초기 JAR에 종족 JSON 44개·스톤 카탈로그 45개·자체 클래스 11개가 있고 원본 Pixelmon/EeveeMega 클래스는 포함되지 않았다. 0.1.2는 클라이언트 툴팁 클래스 2개를 추가했다.
- NeoForge 보완 모듈 `build` 통과. 컴파일에 실제 대상 JAR을 사용했다. `simulateMode()`는 해당 버전에 존재하지만 사용 중단 예고 API이므로 호환 버전을 고정했다.
- 인스턴스/월드 배치 파일은 출력물과 SHA-256 일치 확인했다.
- 0.1.0 초기 JAR SHA-256: `671e849926d2291b1a88f92a14c84f4095384523566dec21f365cad52e545330` (108,709,350바이트). 당시 검증 요약은 `docs/evidence/reports/eeveemega/form-pack-v0.1.0-static.json`에 보존한다.
- 0.1.1 이름 변경판은 빌드/ABI JUnit 2개/전체 CRC 통과. 0.1.0과 ZIP 엔트리 전체를 대조하여 메타데이터·표시 로그 클래스 외 변경이 없음을 확인했다. 중복 모드 ID가 남지 않도록 설치 파일 1개와 배포본 해시 일치도 확인했다. 해당 기록은 `docs/evidence/reports/eeveemega/rename-v0.1.1-static.json`이며 게임 검증을 새로 완료한 자료가 아니다.
- 0.1.2는 빌드와 JUnit4개(기존ABI2+툴팁표시2), 전체CRC 통과. 0.1.1과 data/assets 파일이 모두 동일하다. SHA256 `d7723fac3e21d46fd02cd7e66f1167bd0da90f4ef26144bb1b462eaa80910dac` (108,711,932바이트). 현재 런처의 CheckLocal/VerifyApprovedContent도 새 목록으로 통과했다. 실제 게임 화면은 확인하지 않았다.
- 0.1.3은 Python계약8개와 JUnit4개·빌드·CRC 통과. 0.1.2와 비교하여42종족JSON의 모델배율92개 및 버전메타데이터 외 동일하다. Java클래스·자산·능력치·스폰·성장도/충돌상자데이터는변경하지 않았다. SHA256 `4bcde6ca102f61bcc5faa39194d54bff20109d6eb55f1fdb60dfba9abb7dcbb2` (108,712,377바이트). 서버 자동교체는 가짜JAR fixture로 해시거부/검사전용/정상교체/중복실행을 확인했으며 실제서버는 아직교체대기다.
- **실제 게임 시작, 모델 렌더링, 메가 버튼, 스톤 소비/쿨다운, 전투 능력치/특성, 배틀 종료·기절 복귀, 서버 접속은 아직 시험하지 않았다.** README의 검증 완료 기능으로 반영하지 않는다.

## 사용자 확인 순서

1. 실행 중이라면 사용자가 Minecraft를 완전히 종료한 뒤 같은 테스트 인스턴스를 다시 시작한다. `/reload`만으로 새 모드·Mixin·크리에이티브 탭을 적용할 수 없다.
2. 전용 크리에이티브 탭 또는 `/give @s eeveemega:mega_stone_18 1`로 장크로다일나이트를 확인한다.
3. 키스톤/메가링을 착용하고 장크로다일에게 해당 스톤을 지닌 뒤 전투의 메가 버튼을 확인한다. 목표 메가 종족값은 `85/160/125/89/93/78`, 물/드래곤, Dragonize다. IV·EV·성격·레벨로 계산한 실제 스탯은 이 종족값 자체와 다를 수 있다.
4. 다른 포켓몬/스톤 조합, 일반 플라엣테, 알로라 라이츄에서는 해당 커스텀 스톤이 진화를 일으키지 않는지 확인한다. 싸리용/지가르데는 해제 후 원래 폼과 HP도 확인한다.
5. 멀티플레이를 사용할 때는 서버 `mods/`에도 같은 보완 JAR과 원본 EeveeMega/Pixelmon을 맞춘다. 클라이언트에만 설치한 데이터로 외부 서버의 전투 규칙을 바꿀 수 없다.

되돌릴 때는 사용자 종료 후 보완 JAR과 이 작업의 월드 데이터팩 ZIP만 제거한다. 원본 모드·월드 본문·기존 설정을 교체하지 않았으므로 원래 파일을 덮어쓸 필요는 없다. 기존 포켓몬이 임시 메가 폼인 상태에서 제거하지 않도록 먼저 일반 모습으로 복귀시킨다.

## 소스와 재생성

`estate_mod/mega_compat/`에는 직접 작성한 Java/빌드 설정과 compact 카탈로그만 둔다. 생성한 종족 JSON·모델·텍스처·JAR·ZIP은 저장소에 넣지 않는다.

`tools/build_eeveemega_pack.py`에 `--pixelmon`, `--eeveemega`, `--resourcepack`, 새 `--output` 폴더를 지정하여 생성한다. `tools/test_eeveemega_pack.py`는 `--output`, `--pixelmon`으로 검사한다. `tools/build_eeveemega_bridge.py`에는 같은 JAR 경로와 `--generated <출력/resources>`, 별도 로컬 `--stage` 폴더를 전달한다. 이 명령들은 Minecraft를 실행하지 않는다. `tools/install_eeveemega_bridge.py`는 지정한 인스턴스만 배치하며 원본 입력 해시를 다시 확인한다.
