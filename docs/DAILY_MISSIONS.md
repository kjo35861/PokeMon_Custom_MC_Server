# 일일 임무 · 메뉴 0.16.1 / 모드 0.11.1

## 지급 및 초기화

개인별로 접속 시 아래 슬롯에서 하나씩 총 5개의 임무를 자동 배정하고, 지급 이후의 행동만 집계한다. 같은 날에는 다시 접속하거나 메뉴를 열어도 배정·목표 수량이 바뀌지 않는다. 한국시간(Asia/Seoul) 매일 오전 6시 기준으로 일자·배정·진행도·당일 수령 상태가 바뀐다. 서버가 꺼져 있거나 유저가 오프라인이어도 다음 조회/진행 시 새 날짜를 적용한다. 게임의 `/time`이나 브라우저 시각은 지급 규칙을 바꾸지 못한다.

1. 채집·벌목·채굴
2. 포켓몬 전투
3. 포켓몬 포획
4. 농사·낚시·제작
5. 탐험·육성

날짜 기준은 오전 6시 이전이면 전날의 임무 날짜다. 다음 초기화까지 남은 시간은 화면에서 확인한다.

## 난이도 판단

기본 도구·씨앗·낚싯대·몬스터볼 및 일반 야생 포켓몬 접근이 가능한 서버를 전제로, 전체 20~30분을 목표로 수량을 낮췄다. 이동은 다른 임무와 병행 가능하다. 실제 스폰 밀도·포획률·농장 상태에 따라 소요 시간이 달라지므로 20~30분 달성은 아직 플레이 테스트로 검증하지 않았다.

다이아 등 희귀 자원 강제, 특정 나무·광석·타입·바이옴·시간대 제한, 고레벨 상대, 불리한 상성, 한 방 처치, 노데스, 여러 기술·효과 적중은 운·보유 포켓몬·지형 의존도가 높아 초기 풀에서 제외했다. 우유·꿀·번식·양털·양조·인챈트·모루·진화·알·친밀도·노력치·포켓몬 낚시·규토리·나무열매·탑승 포켓몬 전용 목표는 준비 비용 또는 미연동 기능 때문에 배정하지 않는다. 네더·비행 이동도 필수 목표에서 제외했다.

## 진행 및 보상

- 일반 임무는 생존·모험 모드에서 실제 서버 이벤트로 진행하며 크리에이티브·관전은 제외한다. 제작 결과를 인벤토리에 넣을 때 바닐라 통계 증가를 반영한다.
- 채집 임무는 플레이어가 설치한 대상 블록을 따로 저장해 다시 캐는 반복 진행을 차단한다. 식물은 완전히 성숙한 작물을 파괴한 경우만 수확으로 센다. 다른 모드의 우클릭 재수확 기능은 별도 이벤트 연결이 필요하다.
- 매초 통계 증가분을 비교한다. 접속 전의 누적 통계를 소급하지 않으며 접속/초기화 경계에서 기준값을 새로 잡는다.
- 브라우저는 조회·수령·교체 요청만 보낸다. 진행도·플레이어 UUID·보상 수량을 지정할 수 없다. 서버가 본인의 저장값과 완료 여부를 검사한다.
- 각 임무와 전체 5개 완료 보상에 독립 수령 버튼이 있다. 최종 보상은 5개 **완료**가 조건이며 개별 보상부터 모두 받을 필요는 없다.
- 보상 풀은 미정이다. 현재 버튼은 수령 상태와 영구 수령 기록만 저장하며 아이템·돈·재화를 지급하지 않는다. 화면에도 이 사실을 표시한다. 실제 보상 전달/미지급 기록 처리 정책은 보상 풀을 정할 때 구현해야 한다.
- 저장 성공 후에만 수령 완료로 응답한다. 중복 수령·초기화 전 화면의 오래된 요청은 거부한다. 수령 기록은 새 날짜에도 지우지 않는다.
- `data/pocketmate-missions.json`은 월드별 서버 자료이며 소유권·영지·닉네임·프로필 저장 형식은 바꾸지 않는다. 손상된 임무 파일은 초기화하지 않고 이용 불가로 처리한다.

## 픽셀몬과 현재 환경의 차이

현재 배포 대상은 Fabric 테스트 인스턴스다. 픽셀몬 1.21.1은 NeoForge이므로 전투·포획·육성의 실제 이벤트 구독은 아직 활성화하지 않았다. `PixelmonMissionSignals`는 서버 이식 시 사용할 순수 Java 전달 규칙이며 실제 이벤트 리스너가 아니다. 야생만 계산, 포획으로 끝난 배틀을 처치/승리로 중복 계산하지 않기, 포켓몬/배틀 UUID 중복 방지를 검사했다.

연동 후보는 Pixelmon 공식 `BeatWildPixelmonEvent`, `CaptureEvent.SuccessfulCapture` 및 배틀 종료 이벤트다. 취소 가능한 포획 이벤트는 취소되지 않고 실제 포획 성공이 확정된 뒤 반영하도록 NeoForge에서 최종 확인이 필요하다. 거래/교배/지급 포켓몬은 포획으로 세지 않는다.

전환 조사: [NEOFORGE_MIGRATION.md](NEOFORGE_MIGRATION.md).

## 적용·검증

Java 모드 0.11.0이 추가되므로 재시작이 필요하다. `/webgui reload`만으로 임무 저장·이벤트·교체 코드를 적용할 수 없다. 게임은 에이전트가 실행·종료하지 않으며 사용자가 확인한다. Java 단위 테스트와 모의 브라우저 검사, 라이트/다크 및 160% 글자 크기 검사를 수행했다. 실제 게임·픽셀몬·20~30분 밸런스 확인은 아직 하지 않았다.

## 추가 운영 규칙 · 0.16.1

- **채집 악용 방지:** 플레이어가 설치한 원목·광석 등 대상 블록은 다시 채굴해도 집계하지 않는다. 설치 위치 기록은 일일 초기화·서버 재시작 때 지우지 않는다. 피스톤 이동 시 설치 블록의 표시를 함께 옮겨 위치 변경 우회를 방지한다. 실제 피스톤 게임 동작은 사용자 확인 대기이며 다른 모드의 별도 블록 이동은 추가 연결이 필요할 수 있다.
- **전투 악용 방지:** 향후 NeoForge 픽셀몬 리스너에 사용할 집계 전달 규칙은 자연 스폰임이 서버에서 확인된 야생만 허용한다. PvP, 소유 포켓몬, 명령어 소환, 스포너, 레이드, 출처 불명은 제외한다. 포획 종료를 승리로 세지 않고 포켓몬·배틀 UUID 재전달도 중복 계산하지 않는다. 실제 이벤트 구독은 아직 미연결이다.
- **중복 방지:** 당일 배정 유형을 저장하며 같은 유형은 동시에 두 개 나오지 않는다. 무료 교체 시에도 이미 당일 배정됐던 유형을 다시 선택하지 않는다.
- **달성 가능성:** 전설·색이 다른 포켓몬을 요구하는 목표는 없으며 기존 희귀/고비용/운 의존 임무 제외 정책을 유지한다. 실제 20~30분 목표 시간은 여전히 플레이 검증 전이다.
- **초기화:** 한국시간 오전 6시만 기준으로 삼는다. 임의 재시작·재접속·메뉴 새로고침으로 배정·진행·수령·교체 횟수를 초기화하지 않는다.
- **지급 이후 집계:** 접속·날짜 경계에서 자동 배정하고 바닐라 누적 통계의 기준값을 잡는다. 지급 전 및 교체 전의 늦게 전달된 행동은 새 임무의 지급 시각으로 제외한다. 교체 직전까지의 통계 증가분은 이전 임무로 먼저 처리하고, 교체 직후 새 기준을 잡아 이동·제작 수치를 넘겨받지 않는다.
- **하루 1회 무료 교체:** 모든 슬롯을 합쳐 개인당 하루 1회. 미완료·미수령 임무 하나를 같은 슬롯의 다른 유형으로 바꾼다. 확인창에서 취소하면 차감하지 않는다. 기존 진행도는 사라지고 새 임무는 0부터 시작한다. 다른 4개와 수령 기록은 유지한다. 완료·수령한 임무는 교체할 수 없다. 재시작해도 사용 여부가 유지되며 오전 6시에 다시 1회가 생긴다.

화면 상단에 남은 무료 교체 횟수와 `?` 규칙 안내가 있다. 날짜가 오래됐거나 두 번째 교체 요청이면 서버에서 거부한다. 저장 실패 시 배정·교체 횟수를 메모리에서도 바꾸지 않는다. 자료 형식은 2이며 기존 형식 1의 진행도·수령·설치 블록 기록을 보존해 이관한다. 이전 형식에 없던 지급 시각은 이관 시점을 기준으로 삼고, 이미 저장된 진행도는 소급 취소하지 않는다.
