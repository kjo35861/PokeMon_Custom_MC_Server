## 서버 stop 후 재실행 제보 조사

- 00:36, 00:37, 01:02의 서버 로그에서 종료 명령 뒤 모든 차원의 저장 완료를 확인했다. 일부 종료 뒤 별도 JVM 시작 기록이 있으나 최신 01:02:30 종료 이후 추가 시작 로그와 25565 리스너는 없었다.
- run.bat과 run.sh는 Java를 한 번 실행한다. Windows run.bat의 마지막 pause는 창을 열어둔다. Spigot의 crash 재실행 설정은 켜져 있으나 지정된 start.sh가 없고 이 종료에서 watchdog 재시작 흔적은 없다. 관련 예약 작업이나 서비스도 찾지 못했으며 이전 실행을 요청한 주체는 로그만으로 특정하지 못했다. 서버 설정이나 실행 상태를 변경하지 않았다.

## Pixelmon 기본 메가 모델의 외형 깨짐 조사

- 서버는 메가 호환 모드 0.1.6으로 기동했지만 해당 접속의 클라이언트 로그에는 0.1.5가 로드되어 있었다. 또한 활성화된 eevee-server-resourcepack-recovered.zip은 대상 9개 메가 폼의 리소스 69개를 포함하고 있었다. 그중 43개는 Pixelmon 원본과 경로가 같고 내용이 달랐다.
- 저리더프의 원본 model.bmd를 사용할 때 복구팩의 texture.png가 우선하는 것을 파일 경로와 데이터로 확인했다. 원본 모델과 다른 UV를 전제로 만든 텍스처가 섞여 스크린샷처럼 잘못 표시될 수 있다. 이전 검증은 복구팩의 텍스처 우선순위를 빠뜨렸다.
- 영향받는 메가 폼의 리소스 69개만 제외하는 도구를 만들고 별도 출력 ZIP을 생성했다. 남은 항목, CRC 및 압축 복사본 무결성을 확인했다. 실행 중인 게임과 관리 인스턴스, 원격 배포 목록은 변경하지 않았다. 실제 렌더 확인 대기다.

## Eevee 복구 리소스팩 의존성 확인

- 사용자가 복구 리소스팩을 끈 상태에서 표시가 정상이라고 확인했다. 설치된 모드 세 개를 대조해 현재 카탈로그 36종(포켓메이트 전용 34종 포함)의 모델·텍스처 및 나이트 아이콘 참조에 누락이 없음을 확인했다. 배포 목록이나 설치 파일을 변경하지 않았다.

## Eevee 복구 리소스팩 배포 제외

- 사용자 확인 완료(복구 리소스팩 비활성화 후 메가 폼이 정상 표시됐다고 보고). 원격 클라이언트 팩과 런처의 첫 실행 기본 설정에서 복구 ZIP을 제외했다. Pixelmon 레이더 팩 및 필수 메가 모드 JAR를 유지했다.
- 기존 관리 인스턴스는 런처의 팩 업데이트에서 이전 목록에 있던 ZIP을 정리한다. 새 설치 페이로드에서도 ZIP과 기본 활성화 항목을 제거했다. 실게임 및 Prism을 실행하지 않았다.

- 런처 백엔드 검사 60건과 설치 마법사 페이로드 자체 검증을 통과했다. GitHub에서 현재 배포 목록 19개와 새 설치 마법사의 크기·SHA-256을 확인했다. 이 PC의 기존 팩 상태에도 제거 대상 ZIP이 관리 파일로 등록되어 있음을 확인했다. 실제 인게임 설치 및 접속은 실행하지 않았다.
