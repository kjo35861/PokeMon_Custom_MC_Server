사용자가 요청한 매시간 변경 확인·문서 갱신·일반 커밋/푸시의 범위는 [자동화 운영 문서](../AUTOMATION.md)에 정리했다. 실제 활성화는 로컬 Codex 자동화에서 관리하며 이 저장소에 자격 증명을 저장하지 않는다.

- 첫 업로드 커밋: `66c0eec` — 원격 `main`과 커밋 해시가 일치함을 확인했다. 현재 보관 범위는 후속 정리 커밋에 반영한다.
- `포켓메이트 매시간 작업 기록·푸시`를 현재 채팅의 반복 자동화로 생성했다. 최초 설정 상태 `ACTIVE`, 1시간 간격을 확인했다.
- 변경 없는 경우 커밋을 만들지 않고, 문서·증거 정리 및 검사를 통과한 변경만 일반 푸시하도록 했다. 충돌·인증 실패는 보존·보고하며 강제 푸시하지 않는다.
- 자동화 활성화 기록을 별도 후속 커밋으로 등록한다.

- hover·포커스·클릭으로 열고 Esc/외부 클릭/스크롤/화면 갱신으로 닫는다. 설명이 사이드바의 스크롤 경계에 잘리지 않도록 문서 최상위 고정 레이어를 사용하고 화면 가장자리에 맞춰 배치한다.

## 홈 화면 스크롤 제거 · 0.12.2

- 홈에만 고정 영역 배치를 적용해 제목·타일·안내가 가용 높이를 나눠 사용하도록 변경했다. 기존 타일의 고정 높이로 생기던 넘침을 제거하고 홈의 스크롤을 막았다.

## 영지 설정·홈 지정·마을 이동 · 메뉴 0.13.0 / 모드 0.8.0

- 기록 탭을 영지 설정으로 교체했다. 홈 카드에서 저장 상태·마을 이동·영주 전용 현재 위치 지정 버튼을 제공한다.
- 새 영지는 생성 시 실제 위치·시선을 원자적으로 저장한다. 기존 format 1~3은 최초 소유 청크의 지표 탐색 홈으로 이관하며 기존 영지·금고·마을원·지갑·프로필을 초기화하지 않는다. 정확한 옛 Y좌표는 복구할 수 없어 이 한계를 명시했다.
- 홈 변경은 영주만, 오버월드의 소유 청크 안의 안전한 바닥에서 가능하다. 서버가 실제 플레이어 상태를 검사하며 브라우저 목적지·UUID를 받지 않는다.
- 홈 타일과 이동 탭의 마을 이동 버튼을 실제 영지 홈 이동에 연결했다. 소속 마을원도 사용하며, 비소속은 거부한다. 목적지가 막혔거나 위험하면 거부하고 성공 이동 후 5초 재사용 간격을 둔다. 네더·엔드 청크는 읽거나 쓰지 않는다.
- 신규 홈 테스트 8개를 추가해 Java 58개를 통과했다. 첫 빌드에서는 구형 이관 테스트의 출력 버전 기대값(3)을 발견했으며 새 저장 형식 4에 맞게 갱신한 뒤 전체 빌드를 다시 통과했다.
- 홈 설정 표시·이동 브리지 계약 검사와 기존 차원 요청 80가지·유저 표시 검사 및 JavaScript 구문·CSS 파싱을 통과했다. 실제 게임·브라우저 화면과 텔레포트는 실행하지 않았다.
- 기존 JAR를 0.8.0으로 교체하고 한 번 재시작해야 한다. 화면 파일과 패키지를 준비하고 잠긴 JAR는 종료 후 자동 교체하도록 대기시킨다. 실행 중인 게임/Prism이나 실제 월드 저장 데이터는 조작하지 않았다.

### 첫 입장 한글 닉네임 · 메뉴 0.14.0 / 모드 0.9.0

서버(싱글 통합 서버 포함)에 처음 입장한 플레이어에게 닉네임 입력창이 표시됩니다. 한글 완성형·영문·숫자·밑줄 2~12자를 허용하고 대소문자를 무시한 중복과 현재 접속한 다른 플레이어의 계정명 사용을 거부합니다. 지정 후 재접속하면 입력창이 생략됩니다. `/닉네임`으로 상태를 확인하고, 최초 등록은 `/닉네임 설정 <이름>`으로도 가능합니다. 최초 지정 이후의 임의 변경은 차단합니다.

채팅에는 기존 별 아이콘·칭호 다음에 지정 닉네임이 표시되고, 메뉴 프로필도 닉네임을 표시합니다. 계정 프로필·인증·UUID를 변경하지 않아 영지·재화·꾸미기 소유권은 유지됩니다. 닉네임은 월드의 `data/pocketmate-nicknames.json`에 별도로 저장합니다. 현재 서버 저장소 기준이며 서버를 초기화·교체하면 별도 관리가 필요합니다. 오류가 있는 저장소는 초기화하지 않고 등록을 거부합니다.

**직접 게임에서 확인한 범위:** 별도의 `Pocketmate Nickname QA` 싱글 월드에서 최초 입력창·한글 등록·메뉴 표시·재접속 시 입력 생략과 이름 유지, 다음 명령어의 성공 응답을 확인했습니다.

- `/tp 포켓테스터 ~ ~ ~`
- `/tell 포켓테스터 <메시지>` (재접속 후에도 확인)
- `/pmprofile grant 포켓테스터 title companion`
- `/execute as 포켓테스터 run tp <기존계정명> ~ ~ ~`
- `/execute as 포켓테스터 run pmestate testcredit @s 1` (분리된 테스트 월드만 사용)

플레이어 대상 인자를 쓰는 명령어에 닉네임 조회를 연결했으며 기존 계정명과 선택자도 유지합니다. 모든 명령어를 검사한 것은 아닙니다. `@a[name=...]` 같은 계정명 필터·스코어보드 이름·인증/화이트리스트 관리 및 외부 모드가 별도로 해석하는 인자는 기존 계정명을 사용해야 할 수 있습니다. 실제 전용 서버·동시 접속자·닉네임 자동완성·머리 위 이름표는 이번 게임 검증 범위에 포함하지 않았습니다. 다른 계정명 차단은 등록 당시 접속자 기준입니다.

빌드와 Java 단위 테스트 66개, JavaScript 구문·기존 마을 이동/차원 요청/유저 표시 검사를 통과했습니다. 테스트 인스턴스에는 모드와 메뉴 파일을 교체해 적용했습니다. 기존 개인 월드의 닉네임을 임의로 정하지 않았으며 실제 월드·재화 파일은 공개하지 않습니다. 다른 환경은 서버와 클라이언트의 기존 영지 모드 JAR를 0.9.0 하나로 교체하고 재시작하세요. `/webgui reload`만으로 적용되지 않습니다.
