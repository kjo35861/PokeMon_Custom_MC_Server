포켓메이트 영지·프로필 0.6.0 / 메뉴 0.10
Minecraft Java 1.21.1 Fabric / WebGUI 2.0.0

설치
1. 서버와 플레이어 PC 양쪽 mods에 pocketmate-estates-0.6.0.jar를 넣습니다.
2. 기존 pocketmate-estates JAR는 mods 밖에 백업합니다. 버전 하나만 넣으세요.
3. ZIP의 config/webgui/web 파일들을 서버의 같은 위치에 복사합니다. 싱글에서는 해당 Prism 인스턴스의 minecraft 폴더가 서버이기도 합니다.
4. 반투명 보완 JAR는 client-only에 있으며 플레이어 PC mods에만 넣습니다.
5. 플레이어 PC에 Xaero 월드맵을 설치합니다. 현재 검증 버전은 Fabric 1.21.1용 1.39.12입니다.
6. Java 모드를 교체하면 재실행해야 합니다. HTML/CSS/JS/배경/폰트만 변경했을 때는 /webgui reload 후 F6으로 다시 엽니다.
7. F6 → 영지관리를 누르면 전체화면 관리소가 열립니다. 메뉴로 돌아가기와 X 버튼을 제공합니다.

초기 생성과 구매
오버월드에서 서 있는 무주 청크를 첫 영지로 등록합니다. 생성 확인 창에서 1~24자의 영지 이름을 입력합니다.
생성 위치·플레이어 UUID·월드 경계·소유권은 서버가 검사합니다.
기존 영지는 청크를 유지하고 '<기존 영주명>의 영지' 이름을 자동으로 받습니다.
영토 지도에서 클릭하면 선택/취소하며, 최대 128개 청크를 한 번에 구매할 수 있습니다.
선택한 청크끼리 동서남북 면으로 이어져 기존 내 영지와 연결되어도 구매할 수 있습니다. 선택 순서는 관계없습니다.
대각선만 닿는 연결이나 떨어진 청크는 불가합니다. 이미 소유주가 있는 청크도 구매할 수 없습니다.
하나라도 잘못된 청크가 있거나 저장에 실패하면 전체 구매가 취소됩니다. 일부만 구매하지 않습니다.
청크 좌표 표기와 좌표 입력칸은 화면에서 제거했습니다.

서버 재화
현재 config/pocketmate-estates.json의 freeTestMode 기본값은 true이며 재화 차감 없는 테스트입니다.
실제 서버에서 재화 연동 전 무료 구매를 잠그려면 {"freeTestMode":false}로 설정하고 서버를 재시작하세요.
false는 생성과 청크 구매를 막습니다. 지도/마을원/공지 조회와 영주 관리 기능은 유지합니다.
잔액 차감·실패 환불은 추후 서버 재화 시스템과 함께 연결해야 합니다.

등급과 권한
영주(LORD): 마을 주인, 청크 구매, 초대/추방/등급 변경, 공지/사진 수정, 영지 삭제.
부영주(STEWARD), 영지민(RESIDENT): 소속 영지 지도와 공지, 마을원 현황을 조회합니다.
영주는 한 명이며 등급 조정으로 영주를 추가하거나 양도하지 않습니다. 영주 자신은 추방할 수 없습니다.
관리 권한은 버튼 표시뿐 아니라 서버에서 실제 요청자 UUID로 다시 확인합니다.
한 유저는 한 영지에만 소속됩니다. 마을원은 영주 포함 최대 64명입니다.
블록 설치/파괴 보호, 판매, 양도, 공동 금고는 이번 범위에 포함되지 않습니다.

초대와 마을원
마을원 탭에서 영주가 초대 버튼을 누르면 검색창과 현재 접속 중인 유저 목록을 표시합니다.
검색하면 이 모드가 해당 월드/서버에서 접속을 기록한 유저도 찾을 수 있습니다.
이미 영지에 소속된 유저와 초대 대기 유저는 중복 초대할 수 없습니다.
초대는 7일간 유효합니다. 상대방이 영지 광장 또는 마을원 탭에서 수락해야 영지민으로 가입됩니다.
초대만으로 강제 가입하지 않습니다. 기존 영지 소유자와 다른 영지 소속자는 먼저 소속 문제를 해결해야 합니다.
영주는 등급을 부영주/영지민으로 조정하거나 확인 창을 거쳐 추방합니다.
추방된 사용자는 소속이 사라지지만 해당 영지의 청크 소유권은 그대로 유지됩니다.
마을원 목록에는 닉네임, 등급, 접속 여부, 마지막 접속일을 표시합니다.
접속 중이면 현재 확인 시각, 오프라인이면 모드가 기록한 마지막 접속/종료 시각입니다.

광장
메인에는 대표 사진 공간, 오른쪽 위에는 영주 공지, 그 아래에는 마을원 현황이 있습니다.
영주만 대표 이미지와 공지를 수정할 수 있습니다. 공지는 최대 1000자입니다.
대표 사진은 PC의 PNG/JPEG/WebP 파일(최대 10MB)을 선택하고 미리보기 후 저장합니다.
외부 이미지 주소는 사용하지 않습니다. 화면용 JPEG로 압축해 서버에 저장하고 같은 영지 사용자에게 전달합니다.
WebGUI 이벤트 크기에 맞춰 약 18KB 이하의 JPEG를 사용하므로 원본 해상도로 보관하지 않습니다.

영지 삭제
지도 설정은 왼쪽 메뉴 맨 아래이고 그 위에 영지 삭제가 있습니다. 영주만 삭제 버튼을 봅니다.
삭제 확인 창에 영지 이름을 대소문자와 띄어쓰기까지 정확히 입력해야 버튼이 활성화됩니다.
서버에서도 이름과 영주 권한을 다시 확인합니다.
삭제하면 해당 영지의 모든 청크 소유권, 마을원, 초대, 공지, 사진을 함께 제거합니다. 다른 영지는 유지합니다.
UI에서 되돌릴 수 없습니다. 운영자 백업은 별도입니다. 이번 실제 게임 검증에서는 기존 영지를 삭제하지 않았습니다.

지도

개발자 xaero96. 원본 Xaero JAR는 수정하지 않았으며 이 ZIP에 포함하지 않습니다.

아직 메모리에 불러오지 않은 영역은 어두운 사선으로 표시합니다. 처음 비어 있으면 M으로 월드맵을 한 번 열어보세요.
드래그 이동, 휠 또는 +/− 확대·축소, 내 위치/첫 영지 이동을 제공합니다.

저장과 백업
월드/data/pocketmate-estates.json 하나에 소유권, 영지 이름, 마을원, 초대, 공지, 사진, 접속 기록을 저장합니다.
싱글에서는 saves/<월드명>/data 아래이며 별도 DB 서버가 필요하지 않습니다.
formatVersion 1을 읽어 마이그레이션하며 다음 저장부터 formatVersion 2로 기록합니다.
옛 모드는 새 형식을 읽지 못하므로 운영 중 다운그레이드하지 마세요. 업데이트 전 월드와 이 파일을 함께 백업하세요.
임시 파일을 저장한 뒤 교체하며 직전 상태는 .json.bak에 보관합니다. 저장 실패 시 메모리 상태도 변경하지 않습니다.
손상/누락 데이터는 초기화하지 않고 요청을 차단합니다. 서버 가동 중 저장 파일을 직접 수정하지 마세요.

Java 소스 빌드: Java 21 + Gradle 8.12.1. build.py는 이 PC의 로컬 도구 경로를 사용합니다.

메뉴 v0.8.3 지도 범위
기본 지도 배율을 1/4로 낮춰 같은 화면에서 가로·세로 각각 4배 넓은 지형을 봅니다.
넓은 화면의 축척 눈금은 64블록에서 256블록으로 바뀌며 실제 지도 거리와 일치합니다. 작은 화면·확대 상태에서는 알맞은 눈금을 사용합니다.
지형·소유권 조회 반경 상한은 48청크이며, 자동 갱신 중에도 진행 중인 지형 읽기를 이어갑니다.
기존 영지 소유권과 선택·구매 규칙은 유지합니다. 서버와 클라이언트의 영지 모드를 모두 0.4.1로 교체하고 한 번 재시작하세요.
지형은 Xaero가 불러온 영역만 보입니다. 빈 영역은 M 월드맵에서 한 번 축소해 불러온 뒤 돌아오면 됩니다.

메뉴 v0.8.4에서는 기본 지도 배율이 50%이며 넓은 화면에서 128블록 축척을 사용합니다. 영지 모드는 0.4.1을 그대로 사용합니다. 화면 파일만 복사하고 /webgui reload로 적용하세요.

메뉴 v0.8.5: 휠과 − 버튼의 최대 축소를 50% 배율(넓은 화면의 128블록 축척)로 제한했습니다. 256블록 축척까지 더 축소되지 않습니다. /webgui reload로 적용합니다.

프로필카드 · 모드 0.5.0
별도 data/pocketmate-profiles.json에 UUID별 보유 목록과 착용 아이콘/칭호/배너를 저장합니다. 영지 삭제와 무관하게 유지됩니다.
파일 저장 실패 시 착용은 변경하지 않습니다. 손상된 파일은 자동 초기화하지 않으며 관리자 복구가 필요합니다. 직전 파일은 .json.bak입니다.
기본 아이콘 skin/bulbasaur/charmander/squirtle, 칭호 none/beginner, 배너 none/forest/night를 지급합니다.
추가 지급은 OP 권한 2 이상에서 /pmprofile grant <접속중인플레이어> <icon|title|banner> <항목ID> 를 실행합니다.
예: /pmprofile grant N52_ icon pikachu
예: /pmprofile grant N52_ icon eevee
예: /pmprofile grant N52_ title companion
예: /pmprofile grant N52_ banner sky
지급 후 편집 화면을 다시 열면 목록이 갱신됩니다. 브라우저가 보낸 UUID/보유 목록/이미지 주소는 사용하지 않습니다.
아이콘 PNG 출처·저작권 고지는 profile-assets/SOURCES.txt 및 PokeAPI-LICENCE.txt에 포함합니다.
카탈로그 추가는 ProfileStore.CATALOG와 화면 이미지 에셋을 함께 수정하여 배포합니다. 실제 포켓몬 보유 여부와 아이콘 보유 여부는 별개입니다.
자동 보상/상점 결제는 추후 연결합니다. 현재 서버의 프로필카드 꾸미기이며 다른 유저 조회 기능은 없습니다.

메뉴 v0.10 / 영지 모드 0.6.0 · 영지 금고와 성장
왼쪽 금고·성장 탭에서 금고 잔액, 내 개인 재화, 저축, 승급과 레벨별 한도를 확인합니다.
생성은 레벨 0 / 1청크이며, 영주가 무료로 레벨 1에 승급하면 총 4청크까지 무료 확장합니다.
레벨 / 해당 레벨 승급 비용 / 최대 청크
0 / 0원 / 1청크
1 / 0원 / 4청크
2 / 50,000원 / 6청크
3 / 100,000원 / 9청크
4 / 200,000원 / 12청크
5 / 350,000원 / 16청크
6 / 550,000원 / 20청크
7 / 800,000원 / 24청크
8 / 1,100,000원 / 28청크
9 / 1,500,000원 / 32청크
10 / 2,000,000원 / 36청크

승급 비용은 누적액이 아닌 한 단계 비용이며 금고 잔액에서만 차감합니다. 영주만 승급할 수 있습니다.
영주·부영주·영지민 모두 본인 개인 재화를 금고에 저축할 수 있습니다. 출금·환급 UI는 이번 범위에 없습니다.
청크는 처음 4개까지 무료입니다. 5번째 20,000원, 6번째 22,500원, 이후 2,500원씩 증가해 36번째 97,500원입니다.
한 번에 여러 청크를 구매하면 각 청크의 순차 가격을 합산합니다. 5~6번째 동시 구매는 42,500원입니다.
구매 시 금고를 우선 사용하고 부족한 금액만 영주 개인 재화에서 자동 입금 후 차감합니다. 합계도 부족하면 전체 취소합니다.
잔액 차감·자동 입금·구매 횟수·청크 소유권은 한 파일에 함께 저장합니다. 저장 실패 시 모두 취소됩니다.
구매 확인 이후 가격이 바뀌거나 현재 레벨의 총 보유 한도를 넘으면 취소합니다. 대각선/떨어진 선택/중복 점유 규칙도 유지합니다.
개인 재화는 현재 이 모드의 테스트용 지갑이며 처음 0원입니다. 외부 경제 모드·상점·보상 재화와는 아직 연결되지 않았습니다.
OP 권한 2 이상에서 /pmestate testcredit <접속중인플레이어> <금액> 으로 테스트 지갑을 채울 수 있습니다.
예: /pmestate testcredit N52_ 100000
이 명령은 config/pocketmate-estates.json의 freeTestMode가 true일 때만 작동합니다. false는 이제 테스트 지급만 막으며 일반 구매·저축·승급은 저장된 지갑/금고로 계속 작동합니다.
외부 재화 연결 시 별도 잔액을 단순 복사하면 두 지갑이 됩니다. 추후 사용할 경제 시스템에 맞춰 단일 잔액 원장과 결제 어댑터를 연결해야 합니다.
저장은 기존 data/pocketmate-estates.json의 formatVersion 3입니다. 소유권·금고·성장·개인 잔액·최근 50건 금고 기록을 함께 보관합니다.
formatVersion 1/2는 기존 소유 청크 수를 수용하는 최소 레벨로 이관합니다. 기존 16청크 영지는 레벨 5 / 금고 0원으로 이어지고 청크는 유지합니다.
36청크를 넘는 옛 영지도 삭제하지 않고 그대로 보존하지만 추가 구매는 불가합니다. 옛 버전으로 다운그레이드하지 마세요.
영지 삭제 시 그 영지의 금고·성장·청크가 함께 삭제됩니다. 개인 지갑 잔액과 프로필 꾸미기는 유지됩니다.
모드를 서버/클라이언트 모두 0.6.0으로 교체하고 한 번 재실행합니다. 이후 화면 파일만 수정하면 /webgui reload를 사용합니다.

메뉴 v0.10.1 / 영지 모드 0.6.1: 모든 레벨의 정원을 영주 포함 5명으로 고정했습니다. 추후 레벨별 정원은 EstateRules.MEMBER_LIMITS에서 조정합니다. 기존 인원을 강제 추방하지 않으며 정원 이상이면 추가 초대/가입을 막습니다. 성장 단계 표에 최대 인원을 추가하고, 데스크톱에서 잘리던 금고·성장 화면에 내부 스크롤과 성장 단계 바로가기를 추가했습니다. 자동 갱신 때 스크롤 위치도 유지합니다. 화면은 /webgui reload로 적용할 수 있지만 서버 정원 제한은 게임/서버 재시작이 필요합니다. 사용자 요청에 따라 게임 조작과 실행 테스트는 하지 않았습니다.


0.7.0 업데이트: 마을원·초대 목록에는 서버가 보관한 착용 프로필아이콘·배너만 공개합니다. 보유 목록과 재화는 전달하지 않습니다. 공개 조회는 프로필을 새로 만들거나 저장 파일을 수정하지 않습니다. 프로필 기본 아이콘은 skin(본인 얼굴)이며 기존 착용을 덮어쓰지 않습니다.
클라이언트는 다른 유저의 실제 스킨 얼굴도 표시합니다. 오프라인 스킨 조회는 Minecraft 세션 서비스와 기본 스킨 제공자를 사용하고, 동시에 최대 2건만 비동기 조회합니다. 얼굴 추출도 틱당 최대 2개로 제한합니다. 네더·엔드의 청크 로드/생성/삭제는 하지 않습니다.
