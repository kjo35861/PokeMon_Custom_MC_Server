# 요리 타이밍 도우미 v8 — 다다닥 연타 패턴 지원

두 종류의 마인크래프트 요리 미니게임을 한 프로그램에서 자동 구분합니다. **썰기**는 재료 아래의 공통 표시와 재료 이동을 추적하고, **굽기**는 쟁반/화로의 줄어드는 청록색·노란색 테두리를 추적해 넣기와 꺼내기 때 Space를 누릅니다. 재료의 이름이나 그림은 등록할 필요가 없습니다.

## 실행

기존 도우미를 닫고 **`dist\CookingTimingHelper-v8.exe`** 또는 `start.cmd`를 더블클릭하세요. exe에는 Python과 필요한 라이브러리 및 인식 자료가 들어 있어 별도 설치가 필요 없습니다. 이전 버전은 동시에 켜두지 마세요.

v8은 감자가 줄지어 나오는 **`다다닥! 0/4` 연타 패턴**을 지원합니다. 음식 색이나 줄의 개수 대신 공통 안내 문구와 `/4`를 확인하고, 창이 열린 뒤 80ms 간격으로 네 번 입력합니다. 현재 횟수 0~4도 읽으므로 이미 일부 입력된 상태에서는 나머지만 예약합니다. 연타의 Space 유지 시간은 20ms이며 입력 사이에는 키를 뗍니다. 같은 안내가 계속 보여도 추가 네 번을 시작하지 않습니다. `4/4` 완료 인식, 안내 소실, 게임 종료 시 남은 연타 예약을 취소합니다. 일반 칼질 보정값은 연타 시작 시각에 적용하지 않습니다.

연타 중에는 해당 시각에 도착하는 일반 칼질 예약을 취소해 감자 줄의 조각을 중복 입력하지 않습니다. 창 이후에 도착할 다음 일반 노트는 유지합니다. 로그에는 `다다닥 1/4`부터 `다다닥 4/4`까지 표시됩니다. 현재 지원하는 연타 목표는 제공 영상에서 확인한 4회입니다. 다른 목표 횟수에는 임의로 4회를 입력하지 않습니다.

마지막 V6 녹화를 실제 키 입력 없이 재생해 연타 창 5곳(약 7.63·27.57·45.83·59.63·82.57초)을 감지했고, 각 창에 4회씩 총 20회 예약됐습니다. 배율별 0~4 카운터 인식, 이미 입력된 횟수 반영, 완료/소실 시 취소, 연타 이후 일반 노트, 캡처 지연 및 기존 기능을 포함한 검사 49개를 통과했습니다. 이는 영상·모의 입력 검사이며 실제 서버 판정의 성공률을 측정한 결과는 아닙니다.

v7은 v6에서 Space를 누르고 떼는 동안 같은 재료의 예약이 다시 들어가 두 번 입력되던 스레드 간 경쟁을 수정합니다. 실행 중인 예약을 원자적으로 점유하고, 키 입력을 시작하기 전에 처리 완료로 표시합니다. 실제 키 입력을 시도한 뒤에는 같은 예약을 재시도하지 않습니다. 오래된 예측을 입력 전에 거절한 경우에는 새 관측으로 갱신한 예약을 다시 받을 수 있습니다. 이전 판 입력이 끝나는 동안 다음 판이 시작돼도 완료 기록이 섞이지 않도록 판 세대도 구분합니다.

도마의 재료 감지·이동 예측은 변경하지 않았고, 인접한 정상 노트를 막는 공통 쿨다운을 추가하지 않았습니다. 굽기의 판정 기반 자동 보정과 F11 캡처, 다음 판 대기도 유지합니다. v6 코드에서는 키 입력 콜백 중 같은 ID를 재등록했을 때 썰기·굽기 모두 2회 실행되는 것을 재현했고, v7에서는 각각 1회만 실행됩니다. 검증은 키 입력을 모의한 검사이며 실제 서버 판정 결과는 별도로 확인해야 합니다.

**처음 실행할 때 공통/썰기/넣기/꺼내기 보정값을 모두 0으로 두고, `게임 판정으로 자동 보정`을 켜세요.** 자동 보정은 굽기 넣기/꺼내기에 적용됩니다. `감지만 하기`를 해제하고 F8로 시작합니다. v7의 도마 판정 위치와 타이밍 계산은 v6와 같습니다.

v6는 실제 화면의 초록색 `정확`, 흰색 `빠름`/`느림`, 빨간색 `놓침`을 읽고 별도의 게임 판정 통계를 표시합니다. 실제로 프로그램이 보낸 입력과 시간상 일치하는 고신뢰도 판정만 보정에 사용합니다. 빠름은 해당 동작을 12ms 늦추고, 느림은 12ms 앞당깁니다. 방향이 바뀌면 조정 폭을 줄이며, 정확 판정에서는 값을 유지합니다. 보정은 넣기/꺼내기 각각 최대 ±80ms로 제한하며, 같은 입력은 한 번만 학습합니다. 놓침, 연결할 실제 입력이 없는 판정, 15ms 이상 늦게 실행된 입력은 목표 시각 보정에 사용하지 않습니다.

굽기 기본 기준을 기존 `목표 크기×1.08 + 60ms`에서 **움직이는 테두리가 고정 목표 틀과 같은 크기에 도달하는 시점**으로 바꿨습니다. 화면이 멈춘 것을 새 속도 관측으로 계산하지 않으며, 같은 판에서 정상적으로 관측된 테두리 진행 주기도 이용합니다. 충분히 안정된 예측은 최대 650ms의 짧은 렌더링 정지 구간을 넘길 수 있습니다. 화면 전환/정지/창 비활성화 취소와 예약 만료 제한은 유지합니다.

로그의 `예약 오차`는 프로그램의 내부 실행 시각 측정입니다. **실제 게임 정확도의 기준은 `게임 판정 정확/빠름/느림/놓침` 줄과 게임 판정 통계입니다.** 새 영상은 기존 버전으로 플레이한 녹화이므로, v6가 그 영상의 판정 결과를 바꿨다고 해석하면 안 됩니다. v6의 실제 성공률은 새 버전으로 플레이한 결과에서 확인해야 합니다.

v5는 굽기의 `입력 생략 · stale prediction` 취소 문제를 수정했습니다. 테두리 자체를 마지막으로 본 시각과, 현재 미니게임 화면에서 기존 예약이 유효한지 확인한 시각을 구분합니다. 목표 부근에서 테두리가 겹쳐 잠깐 감지되지 않거나, 늦게 누르는 보정 때문에 대기하는 동안에도 이미 계산한 예약을 갱신합니다. 무보정 기준 시각을 지났다는 이유로 실제 입력 예약의 갱신을 중단하던 부분도 수정했습니다.

예약은 무제한 유지하지 않습니다. 보정 전 목표 시각 이후 최대 260ms까지만 유효하며, 이는 공통/개별 보정으로 합계 200ms 늦추는 설정과 짧은 처리 지연을 수용하는 범위입니다. 미니게임 종료·화면 전환·정지·게임 창 비활성화 시의 취소는 유지합니다. 테두리 소실을 보완해 입력한 경우 로그에 `테두리 소실 보완`을 표시합니다. 입력이 생략되면 마지막 테두리/재료 관측과 화면 확인 경과 시간도 함께 표시합니다.

v4는 화면 감지와 키 입력을 별도 스레드로 처리합니다. GPU 화면의 실제 표시 시각으로 움직임을 계산하고, 예측한 시각에 고해상도 타이머로 입력을 예약합니다. 같은 프레임을 반복 계산하지 않으며, 시간 구간을 기준으로 속도를 추정해 FPS 변화와 일시적인 인식 튐의 영향을 줄였습니다. 키를 누르는 동안에도 화면 감지는 계속됩니다.

두 게임 모두 **감지만 하기** 체크를 해제하고 게임 화면에서 **F8**을 누르면 됩니다. 굽기는 도마나 판정선 지정이 필요 없습니다. 로그에 `굽기 넣기` / `굽기 꺼내기`가 표시됩니다. 처음에는 감지 전용 상태로 확인하고, 썰기의 판정선을 조정하려면 아래 순서를 따르세요.

1. **F11 전체화면도 지원합니다.** 게임 화면에서 **F8**을 누르면 썰기/굽기 화면을 기다립니다. 썰기의 판정선 위치를 확인하려면 **① 화면 잡기 (3초 후)**를 누르고, 3초 안에 게임을 클릭해 도마가 보이게 하세요. 화면을 맞출 때는 먼저 연습하기를 이용하세요.
2. 미리보기의 초록 테두리가 **도마 전체**와 맞는지 확인합니다. 틀리면 **② 도마 직접 지정** 후 도마만 드래그하세요. 칼과 냄비는 도마 영역 밖입니다.
3. 빨간 세로선이 **칼이 내려오는 고정 위치**인지 확인합니다. 틀리면 **③ 판정선 지정**을 누르고 그 위치를 클릭하세요. 움직이는 재료의 세로선과 혼동하지 마세요. 기본값은 영상 기준 도마 왼쪽에서 9% 지점입니다.
4. 처음에는 **감지만 하기**를 켜둔 채 **F8**로 시작하고 게임 창을 클릭합니다. 재료가 칼 위치를 지날 때마다 로그에 감지가 1회씩 나오는지 확인하세요. 이 모드에서는 키를 보내지 않습니다.
5. **F9**로 정지하고 **감지만 하기** 체크를 해제합니다. 다시 **F8**로 켜고 게임 창을 클릭해 요리/연습을 진행하세요. 설정 변경은 다음 시작부터 적용됩니다.

**F9는 정지**, F8은 시작/정지 전환입니다. **Esc로 미니게임을 닫아도 매크로는 종료되지 않습니다.** 미니게임이 끝나거나 결과 창이 뜨면 다음 판을 기다립니다. 다음 판이 다른 종류여도 썰기/굽기를 다시 구분합니다. 게임이 아닌 창으로 이동한 동안에는 키를 보내지 않고 대기합니다. 다음 요리 시작과 레시피 선택은 직접 하세요.

F11 전환이나 창 크기 변경 시 종료하지 않고 도마를 다시 찾습니다. 판정선은 도마 안에서 사용자가 지정한 비율을 유지합니다. 게임 창이 같은 프로세스 안에서 다시 생성되는 경우에도 따라갑니다. 마인크래프트 자체를 완전히 종료하고 다시 실행했다면 도우미를 다시 시작하세요.

전체화면은 GPU 화면 캡처(DXGI)를 우선 사용하며, 이용할 수 없는 경우 GDI 호환 캡처를 시도합니다. 화면 전환 중 일시적으로 캡처가 실패해도 종료하지 않고 복구를 기다립니다.

## 타이밍 조정

- 입력이 늦으면 보정을 `+5`, `+10`ms처럼 올리세요. 양수는 일찍 입력합니다.
- 입력이 빠르면 `-5`, `-10`ms처럼 내리세요. 음수는 늦게 입력합니다.
- 공통 보정 외에 **썰기 / 굽기 넣기 / 굽기 꺼내기** 보정값을 따로 지정할 수 있습니다. 세 칸 모두 양수는 일찍, 음수는 늦게 입력합니다. 기존 v3에서 맞춘 보정값은 지연 처리 방식이 달라졌으므로 먼저 0부터 다시 확인하세요. 설정 변경은 정지 후 다시 시작할 때 적용됩니다.
- 먼저 판정선 위치가 맞는지 확인하세요. 화면 녹화의 판정 글자는 실제 입력보다 늦게 보일 수 있습니다.
- 게임 창이 활성 상태이고 해당 미니게임 화면이 보일 때만 동작합니다. 굽기는 화면 아래의 한국어 넣기/꺼내기 안내도 함께 확인하므로 그 부분을 가리지 마세요. 창을 가리거나 최소화하면 사용할 수 없습니다.
- 화면을 캡처할 때 도마가 아닌 화면을 잡으면 다시 캡처하세요. GUI 배율, 셰이더, 도마 디자인 변경도 재설정이 필요할 수 있습니다.

상태창의 **화면 지연**은 캡처 완료와 GPU 표시 시각 사이의 차이입니다. **예약 오차95%**는 예약한 시각과 프로그램이 키를 보낸 시각 사이의 내부 측정값입니다. 감지 모드에서는 키를 보내는 대신 콜백 시각을 측정합니다. 게임이 판정한 빠름/느림 오차와는 다른 값입니다.

실제 게임의 틱, 렌더링, 프레임 정지, 입력 처리 및 판정 기준 때문에 게임 판정의 편차가 0이 되는 것을 보장할 수 없습니다. 일정하게 빠르거나 느린 현상은 해당 동작의 개별 보정으로 맞추고, 들쭉날쭉한 지연은 예약 오차와 화면 지연을 함께 확인하세요.

## 재료 종류와 검증 범위

아이템별 이미지 인식은 사용하지 않습니다. 공통 썰기 표시가 있는 재료는 표시를 우선 추적합니다. 표시가 없는 경우에도 배경 차이와 움직임으로 추적하며, 이 경로는 배경을 학습하는 첫 약 0.55초 동안 준비가 필요합니다. 좌우로 지나가는 얇은 박자선은 재료에서 제외합니다.

굽기는 음식 이미지 대신 공통 테두리를 사용하며, 테두리가 목표 크기에 도착하는 시간을 예측합니다. 영상에서 관찰한 테두리와 입력 애니메이션 차이를 보정했습니다. 음식을 인식해 굽기 시간을 정하거나, 일정 시간마다 반복 입력하는 방식은 아닙니다.

다만 **아직 보지 못한 모든 실제 레시피에서 성공을 보장할 수는 없습니다.** 도마와 구별이 거의 안 되는 재료, 겹치는 재료, 다른 조작을 요구하는 노트, 안내 언어나 화면 배치가 다른 미니게임은 추가 확인이 필요합니다. 현재 지원 범위는 제공된 영상의 Space 썰기 및 Space 넣기/꺼내기입니다.

첨부 영상 516프레임을 실제 입력 없이 분석해 재료 4개를 각각 한 번씩 감지했습니다. 색·도형·크기·속도 및 공통 표시 유무가 다른 모의 재료 18가지도 각 한 번씩 감지했습니다. 정지한 물체, 반대 방향 이동, 어두워진/닫힌 도마, 비활성 창의 입력 차단 검사를 통과했습니다. 다른 실제 재료의 게임 판정은 아직 확인하지 않았습니다.

## 소스와 개발

- `app.py`: 한글 GUI, 화면 캡처, 전역 단축키, 실행 루프
- `vision.py`: 공통 표시/움직임 감지, 재료별 추적, 도착 시간 예측
- `grill.py`: 굽기 화면 구분, 청록색 넣기/노란색 꺼내기 테두리 감지 및 타이밍 예측
- `win_input.py`: Windows 전경 창 확인 및 Space scan-code 입력
- `screen_capture.py`: DXGI 전체화면 캡처, 모니터 좌표 처리, 캡처 복구
- `session.py`: 미니게임 사이 대기 및 화면 크기 변경 후 도마 재탐색
- `motion.py`: 시간 구간 기준 움직임 추정 및 인식 이상치 완화
- `feedback.py`: 실제 게임 판정 글자 인식 및 동작별 자동 보정
- `burst.py`: 다다닥 `/4` 안내와 완료 인식, 연타 창별 입력 예약
- `scheduler.py`: 취소 가능한 고해상도 입력 예약 및 감지/입력 분리
- `verify_timing.py`: 프레임 중복·지연·연속 노트 및 키를 보내지 않는 예약 시각 검사
- `verify_burst.py`: 배율별 연타 안내·완료 인식, 4회 제한, 창 소실 취소, 다음 일반 노트 및 영상 재생 검사
- `verify_grill_recovery.py`: 테두리 소실 및 늦춤 보정에서 v4의 예약 취소를 재현하고 v5의 예약 유지·취소 경계를 검사
- `verify_verdicts.py`: 실제 영상의 판정 글자, 입력 연결, 자동 보정 방향·범위, 짧은 화면 정지 대응 검사
- `verify.py`: 키 입력 없이 영상 재생 및 합성 재료 검증

```powershell
python -m pip install -r requirements.txt
python app.py
python verify.py --video '썰기영상.mp4' --grill-video '굽기영상.mp4' --report verification.json
```

Windows 입력은 [Microsoft SendInput](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-sendinput)을 사용합니다. 게임이 관리자 권한으로 실행되면 일반 권한 프로그램의 입력이 전달되지 않을 수 있습니다. 정상 종료 또는 예외 발생 시 눌렀던 Space를 해제합니다. DXGI 캡처는 [DXcam](https://github.com/ra1nty/DXcam)을 사용합니다.

v2에서는 Esc를 누르는 동안의 지속 실행, 해상도 변경, 일시적인 캡처 오류, 같은 게임 프로세스의 창 재생성, 보조 모니터 좌표를 검사했습니다. 첨부 영상을 두 판 연속 재생하고 중간에 화면 크기를 바꿔 재료 8개를 감지했습니다. 실제 F11 게임 플레이의 성공 판정은 별도로 확인해야 합니다.

v3은 새 영상의 넣기 2회/꺼내기 2회, 음식 색이 달라지는 모의 테두리, 굽기 화면이 없는 경우의 입력 차단, 썰기→굽기→썰기 자동 전환을 검사합니다. 영상 재생 검증은 실제 키를 보내지 않으며 실제 서버에서의 성공 판정을 보장하는 검사는 아닙니다.

v4 모의시험에서는 60ms 간격의 노트 240개에 캡처 지연, 처리 지연, 중복 프레임을 섞었습니다. 같은 시험에서 v3는 놓침 85개/추가 입력 3개, v4는 놓침 0개/추가 입력 0개였고, 95% 절대 시점 오차는 29.717ms에서 1.389ms로 줄었습니다. 이 수치는 합성 입력의 비교 결과이며 실제 서버 판정 정확도가 아닙니다. 실제 키를 보내지 않는 Windows 타이머 검사도 별도로 실행합니다.

v5는 넣기/꺼내기 각각 0·100·200ms 늦춤 보정에서 테두리를 숨긴 재현 검사를 통과했습니다. v4라면 `stale prediction`으로 취소될 6개 경우에서 예약 유효성이 유지되는 것을 확인했습니다. 미니게임 종료 시 예약 제거, 예약 유지 시간 초과, 정지 시 취소도 별도로 검사했습니다. 실제 서버에서 장시간 플레이하며 확인한 결과는 아닙니다.

v6의 판정 인식은 이전 영상의 정확 3회/빠름 1회, 새 영상의 빠름 9회/느림 1회/놓침 5회와 대조했습니다. 새 녹화의 결과 화면 `정확 0, 좋아 10`과 일치하는 판정 읽기 결과입니다. 이는 녹화된 기존 플레이 판정의 인식 검증이며, v6의 실제 플레이가 전부 정확이라는 뜻은 아닙니다.

exe 재빌드:

```powershell
python -m pip install pyinstaller
python -m PyInstaller --noconfirm --clean --onefile --windowed --collect-all dxcam --add-data 'assets;assets' --name CookingTimingHelper-v8 --distpath dist --workpath build app.py
```
